# GhostPacket — Repository structure (V3 "Skeleton Crew" monorepo)

## Skeleton rule
One skeleton, several apps. The skeleton is `crates/ghostpacket-core` + `packages/ghostpacket-sdk` + `packages/ghostpacket-ui`. Every app under `apps/` is built only from these packages: an app never imports another app, never imports a package by relative path, and never imports the WASM glue directly (checked by `scripts/kiroween-audit.mjs`).

## Separation rule
All **cryptography, compression, DSP (FSK and future transports), FEC and fountain code** logic lives only in `crates/ghostpacket-core`. The server verifier (`crates/ghostpacket-verifier`) reuses that crate instead of reimplementing it. TypeScript only does:
- hardware I/O (speaker, microphone, screen, camera), and the opt-in proof upload in `outbox.ts`;
- UI state and Canvas rendering;
- calls into WASM through `packages/ghostpacket-sdk/src/wasm-bridge.ts` (the only module that imports `packages/ghostpacket-sdk/wasm/`).

## Conventions
- Rust: `snake_case` modules, errors as `Result<T, GhostError>`, bounds as `SCREAMING_SNAKE_CASE` constants.
- TypeScript: React components in `PascalCase.tsx`, utility modules in `kebab-case.ts`.
- Packages ship TypeScript source; apps compile it (`transpilePackages`) and import subpaths: `ghostpacket-sdk/<module>`, `ghostpacket-ui/<Component>`. Only `packages/ghostpacket-sdk/dist` is compiled JavaScript.
- Each app runs `scripts/sync-app-assets.mjs` before `dev` and `build`, and adds `@source` lines for the packages in its global CSS (Tailwind v4).
- Error codes shown in the UI are `SCREAMING_SNAKE_CASE` (`CRC32_MISMATCH`); messages are English sentences.
- Field presets are defined twice and must stay identical: `packages/ghostpacket-sdk/src/presets.ts` and `crates/ghostpacket-core/tests/common/mod.rs`.
